# Kore Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Kore's core: accounts, personal and shared spaces, quotas, chunked uploads, trash, search, text preview, admin panel, and Docker deployment. Public share links are a separate later plan.

**Architecture:** A Go API (stdlib `net/http`, SQLite via `modernc.org/sqlite`, no cgo) owns all data. Files are stored as opaque blobs; folders, names, quotas and settings live in SQLite. A Next.js (SSR, App Router) app renders the UI and forwards the session cookie to the API on the server. A Caddy container exposes one origin, sending `/api/*` to Go and everything else to Next.js, so large transfers bypass Node.

**Tech Stack:** Go 1.23+, `modernc.org/sqlite`, `golang.org/x/crypto/argon2`, `github.com/pelletier/go-toml/v2`; Next.js (App Router, TypeScript), Tailwind, vitest, Playwright; Docker Compose, Caddy.

**Spec:** `docs/superpowers/specs/2026-10-21-kore-design.md`

## Global Constraints

- Backend is Go. Not Python, not JavaScript/Node, for anything but the Next.js UI.
- Frontend is Next.js **with SSR**; no static export, no client-only routing.
- Auth is email + password only; roles are exactly `admin` and `user`; **admin creates every account** (no signup, no invite links).
- Config file `kore.toml` holds only: listen port, bind address, data directory, first admin email/password. Everything else is in the admin panel (SQLite).
- Default bind address is `127.0.0.1`; `0.0.0.0` is a supported value.
- Storage is the mdadm mirror at `/mnt/mirror`; no ZFS code. Files, trash and SQLite live under one data directory (one volume).
- The app refuses to start unless a marker file proves the real volume is mounted.
- Quotas are enforced by the app: trashed files count toward the owner's quota until purged; shared-space files count against the uploader; in-flight uploads reserve quota.
- Shared space: any user may rename, move, delete anything. Admins cannot browse other users' personal spaces (usage totals only).
- Uploads are chunked and resumable (Cloudflare Tunnel rejects bodies over 100 MB); name collisions keep both with a numbered suffix; max file size is an admin setting, unlimited by default.
- Preview only for text-like files; no in-browser editing.
- UI: dark, compact, list view by default, ~6px corners, accent `#5b8def`, sidebar with My files / Shared space / Trash / storage meter. English only, all strings externalized so Russian can be added; Unicode filenames must work.
- Login is rate-limited; deleting a user requires the admin to delete or reassign that user's files first.

## Review Focus

1. Moving a folder into itself or its own descendant is rejected (no cycles).
2. Two uploads of the same name into one folder concurrently both succeed with distinct names.
3. A user at 100% quota can still delete files and empty trash to free space.
4. Filenames with Cyrillic, spaces, `/`-lookalikes, `..`, and 255+ characters are stored and downloaded intact or rejected cleanly, never escaping the data directory.
5. A chunked upload interrupted and resumed (including after server restart) completes with identical bytes; abandoned uploads release their quota reservation.
